방법1 : Bean validation의 groups 기능 사용
방법 2: ItemUpdaetForm, ItemSaveForm으로 등록/수정용의 별도의 2개의 객체를 만든다. 

방법 1로 구현된 코드를 보면 알겟지만, 내가 봐도 이건 아니다 싶을 정도로 복잡하다. 그래서 실무에서는 groups 기능을 전혀 쓰지 않고, 별도의 2개의 객체를 만든다.
왜냐하면 지금이야 등록/수정폼의 데이터가 비슷비슷하지만, 실제 서비스에서는 예를 들어 회원 가입(등록), 회원 가입 정보 수정(수정) 시, 넘어 오는 데이터의 종류가 너무나도 다르다.
그래서 하나의 객체를 공통적으로 사용할 수가 없다. 그래서 실무에서는 보통 방법 2로 등록폼용 객체와 수정폼용 객체를 따로 분리한다.

더 정확히 말을 하면, 우선 등록 폼 데이터는 Item 도메인 객체와 매칭하지 않는다. 왜냐하면 ITem 도메인 객체의 데이터 외에 무수히 다른 데이터들이 같이 들어와야 하기 때문이다.
ex) 갱신일, 등록자명 등
그리고 수정 폼 데이터는 우선 등록 폼 데이터와는 완전히 다르다. 예를 들어 등록 시에는 로그인 ID, 주민번호 등의 데이터가 넘어 오지만 수정 시에는 로그인 ID, 주민번호를 변경하지 않기 때문에
그 데이터는 수정 폼에 없다. 그리고 등록 시 검증 로직과 수정 시 검증 로직 또한 많이 달라진다.
그래서 수정 폼 사용 시 등록 폼 객체를 그대로 재사용 하지 못하니깐 따로 수정 폼 객체를 만들어 주는 것이다.
그리고 컨트롤러에서 어찌됐든 등록 폼/수정 폼 객체를 Item 객체로 변환해야 하는데, 실무의 대부분의 경우에는 폼 안의 데이터만으로 ITem 객체로 변환이 되는 일은 거의 없다.
DB를 통해 추가 데이터를 들고 와서 ITem 객체로 변환하는 일이 대부분이다.
