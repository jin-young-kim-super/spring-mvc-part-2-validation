상품명에 아무것도 안 적거나, 가격/수량에 영어가 포함되거나 하는 경우에 아무런 검증 로직이 없다면
사용자 화면에서는 Bad Request 오류 화면이 나온다.
-> 근데 이건 UX 측면에서 매우 좋지가 않다. 왜냐하면 사용자는 오류 화면이 나타남으로써 자기가 여태껏 썻던 정보를 전부 잃어버리게 되면서 다시 처음부터 기입을 해야 하기 떄문이다. 
그렇게 되면 그 서비스를 모두 떠나갈 것이다.
※ 웹 서비스는 폼 서비스 오류 발생 시, 고객이 입력한 데이터를 유지한 상태로 어떤 오류가 발생했는지를 친절하게 알려주어야 한다


검증법에는 크게 두가지 방법이 있다. 
- 클라이언트에서 검증
-> 보안에 취약하다. 조작이 가능하기 때문이다. 막말로 POST MAN으로 보낼 수가 있다. 

- 서버 검증법 
-> 보안에는 강하나, 검증 정보가 사용자에게 전달되기까지 시간이 소모된다.

결론 : 위 2가지 방법을 적절히 혼용 사용하여야 한다. 그러나 서버에서의 검증이 필수이다.
※만약 HTTP API 방식이면 API 스펙을 잘 정의해서 응답 API에 오류 내용을 친절히 적어 줘야 한다.
그리고 먼저 검증 로직을 개발자가 직접 구현해보고, 그걸 스프링과 타임리프로 전환을 해볼 것이다.
